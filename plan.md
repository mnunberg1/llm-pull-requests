# LLM PR Grader – Project Plan

Goal: grade PRs against the Pull Request Guidelines, refine offline until grades
match human judgement, then wire into GitHub.

## Target Repo

To be read in the repo file named by the active configuration (see below).

### Active configuration

A configuration (`<name>.cfg`, with a `repo=repos/<name>.md` line) selects the
repo being graded. Every run, review and script call works on exactly one
active configuration, and none may start without one:

- Scripts take it from `--config`, else `$PRDOCS_CONFIG`, else the symlink `active-config.cfg`.
- `active-config.cfg` is a symlink (gitignored) to the active `<name>.cfg`;
  switching configurations means repointing it.
- The `grade-review` skill needs it: it uses a `.cfg` I name, else
  `$PRDOCS_CONFIG`, else the symlink, asks me to pick one and creates the
  symlink if there is none, and passes `--config` on every script call.
- In a Claude console session, the active configuration is shown on the bottom
  status bar (`.claude/statusline.sh`, set in `.claude/settings.json`), like
  the branch in a git prompt: `● <name>.cfg  <repo file>  <owner/name>`, or
  `○ NO ACTIVE CONFIG`. Switching repoints the symlink and re-runs the change
  check.

1. Ask Claude to regenerate `scripts/` from `scripts.md`, following `plan.md`

2. `scripts.md` is the source of truth. To change script behavior, edit

   scratch run-id, and `serve.py` on it.


## Model output contract

The grader must return only JSON, nothing else. <!-- AI BEGIN -->Three scores
(atomicity, description, readability) and no others; <!-- AI END -->the
comments carry the detail. Each comment carries a 1-5 sentiment
(1 very negative, 5 very positive) that shows how the model viewed the code.
It is display only and never feeds any score:

<!-- AI BEGIN -->

```json
{
  "pr": 123,
  "scores": {"atomicity": 3, "description": 4, "readability": 2, "test_readability": 4},
  "files": [{"path": "src/a.cc", "readability": 2}, ...],
  "overall": 2,
  "overall_with_tests": 3,
  "dirs": [{"path": "src", "readability": 2.3, "files": 3, "lines": 120}, ...],
  "comments": [{"sentiment": 4, "text": "Short comment, ~150 chars max, no implementation details."}, ...],
  "effort": {"author_minutes": 30, "review_minutes": 180}
}
```

The model returns `scores`; `grade.py` adds `overall` (not asked from the
model): 0.75 × readability + 0.125 × atomicity + 0.125 × description, rounded
half up, so readability counts most. Results from before the three scores have
only `overall`.

`readability` covers the non-test files; `test_readability` is the model's
score for the test files (judged by a looser threshold, omitted if the PR
changes none) and `files` its readability score per changed file. `grade.py`
also computes, not the model: `overall_with_tests`, the same formula with
readability replaced by the source and test scores weighted by their share of
the changed lines (equal to `overall` without test changes), and `dirs`, the
mean file score of every directory above the scored files, weighted by changed
lines. Test files are those under the repo file's test paths.

`effort` is the model's rough estimate, in minutes, of the human effort behind
the change. `author_minutes` assumes an author who is not intimately familiar
with the codebase and counts what they actually did, so it is low for
LLM-generated code. `review_minutes` assumes a maintainer who knows the
codebase and treats LLM-generated code as harder to review. It is display
only and never feeds any score. A heuristic only.

## Workflow

### Fetch PRs

Fetch 30 recent PRs (open and closed) once that conform to the criteria 
in repo.md. Fetch 10 of each: small, medium, and large. 
Size is in  respect to core source code changes only, so disregard tests 
and comments (when considering size), unless the 
PR is about the test infrastructure itself.

           Small: < 150 lines 
           Medium: 150-500 lines
           Large: > 500 lines

### Grading

Grade them all into <!-- AI BEGIN -->results/<owner_name>/<run-id><!-- AI END -->/ by using the grading script<!-- AI BEGIN -->,
which runs the model through `scripts/agent.py`: Claude by default, or Codex or
any command that reads a prompt on stdin and prints a reply (see RUNNING.md)<!-- AI END -->

### Viewing

Run `scripts/serve.py <run-id>` and open the page in a browser. Each PR shows
its GitHub link, title, author, the model's 1-5 score and its comments with
sentiment badges, an optional 1-5 grade of mine, and a notes box. Saving
writes <!-- AI BEGIN -->grades/<owner_name>/<number>.txt<!-- AI END -->.

### Review Loop

- Run the `grade-review` skill: Claude walks me through the graded PRs,
records my feedback in grades/, answers questions about the grader's
rationale, and proposes generic diffs to rubric.md, prompt.md and
plan.md, and repo-specific ones to the repo file. I approve each diff.

- Adjust rubric.md, re-run into a new <!-- AI BEGIN -->results/<owner_name>/\<run-id><!-- AI END -->, compare. 
- Repeat until agreement is good enough.

## Later: GitHub integration

Once calibrated, a GitHub Action on pull\_request (opened, synchronize) runs
fetch + grade for that PR and posts a single short comment or check status.
Start in a silent/log-only mode before posting publicly.
