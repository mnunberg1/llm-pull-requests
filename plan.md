# LLM PR Grader – Project Plan

Goal: grade PRs against the Pull Request Guidelines, refine offline until grades
match human judgement, then wire into GitHub.

## Target Repo

To be read in file REPO.md

## Directory layout

```
ROOT/
    guidelines.md      # the Pull Request Guidelines doc, unchanged
    rubric.md          # criteria and review order, weighed qualitatively; updated with human approval
    prompt.md          # grading prompt (wording and nature of the grading); updated with human approval
    REPO.md            # repo-specific information
    CLAUDE.md          # project instructions for Claude
    scripts.md         # spec for regenerating scripts/
  scripts/             # GENERATED from the files above, gitignored
    fetch_prs.py       # pulls recent PRs via gh CLI into data/prs
    grade.py           # builds prompt.md + guidelines + rubric + PR, runs the model, writes JSON result; owns the JSON output format
    serve.py           # local server: serves the grading page, saves grades to text files
  data/<REPO>          # GENERATED, gitignored
    prs/<number>/      # cached PR data, fetched once
      meta.json        # title, author, description, labels, state
      commits.json     # commit list with messages
      diff.patch       # full diff
  grades/              # GENERATED by the page, gitignored
    <number>.txt       # my optional 1-5 grade ("overall: N") then "notes:" and free-form text
  results/             # GENERATED, gitignored
    <run-id>/          # one folder per rubric or prompt version; never overwritten
      <number>.json
      summary.txt      # per PR: number, model overall, my grade, then its comments
```

## Generating the scripts

Only the specs are committed; `scripts/` is rebuilt from them by an LLM
session (Claude Code) in this repo.

1. Ask Claude to regenerate `scripts/` from `scripts.md`, following `plan.md`
   and `CLAUDE.md`. Delete the old `scripts/` first for a clean rebuild.
2. `scripts.md` is the source of truth. To change script behavior, edit
   `scripts.md` (or `prompt.md` / `rubric.md` for the grading itself) and
   regenerate; do not hand-edit generated scripts.
3. Wording and nature of the grading live in `prompt.md` and `rubric.md`. Only
   the JSON output format and mechanics live in the scripts.
4. Check a rebuild by running `fetch_prs.py --limit 3`, `grade.py` into a
   scratch run-id, and `serve.py` on it.


## Model output contract

The grader must return only JSON, nothing else. No per-criterion scores; the
comments carry the detail. Each comment carries a 1-5 sentiment
(1 very negative, 5 very positive) that shows how the model viewed the code.
It is display only and never feeds any score:

```json
{
  "pr": 123,
  "overall": 3,
  "comments": [{"sentiment": 4, "text": "Short comment, ~150 chars max, no implementation details."}, ...]
}
```

## Workflow

1. Fetch the last 20–30 PRs (open and closed) once.
2. Grade them all into results/<run-id>/.
3. Run `scripts/serve.py <run-id>` and open the page in a browser. Each PR shows
   its GitHub link, title, author, the model's 1-5 score and its comments with
   sentiment badges, an optional 1-5 grade of mine, and a notes box. Saving
   writes grades/<number>.txt.
4. The page can filter to PRs where the model and I differ by 2+ points.
   summary.txt is regenerated on each save.
5. Interactive LLM session prompts for adjustments to rubric.md and plan.md
   based on feedback.
6. Adjust rubric.md, re-run into a new results/\<run-id>, compare.
7. Repeat until agreement is good enough.

## Later: GitHub integration

Once calibrated, a GitHub Action on pull\_request (opened, synchronize) runs
fetch + grade for that PR and posts a single short comment or check status.
Start in a silent/log-only mode before posting publicly.
